# Что Такое Factoriat

Factoriat — это лёгкий decision engine для доменного Go-кода. Он помогает отделить принятие решения от исполнения side effects.

Обычный код со временем часто превращается в набор вложенных условий:

```go
if player != nil && seat != nil && !folded && state == player.SitOut {
	// mutate table
	// update repository
	// create timer
}
```

В таком коде смешаны три разные вещи:

- сбор данных;
- принятие решения;
- исполнение решения.

Factoriat предлагает разделить это на понятные части:

```text
Factor -> Predicates -> Facts -> Apply
```

Факториaт получает снимок состояния, проверяет правила и возвращает типизированные факты-решения. Он не пишет в БД, не создаёт timers, не берёт locks и не мутирует application state.

## На Что Это Похоже

Factoriat объединяет несколько известных идей:

- Specification / Predicate Pattern — сложные условия получают имена.
- Rules Engine — входные данные проходят через правила и дают результат.
- Decision Table — rules builder читается как таблица решений.
- Domain Events / Command Facts — результат решения выражен типизированными фактами.
- Separation of Decision and Execution — решение отдельно, исполнение отдельно.

## Главная Формула

```text
Factoriat = Factor + Predicates + Rules + Facts
```

`Factor` отвечает на вопрос: “Что мы знаем сейчас?”

`Predicates` отвечают на вопрос: “Какие доменные условия истинны?”

`Rules` отвечают на вопрос: “Какие решения следуют из этих условий?”

`Facts` отвечают на вопрос: “Что должно быть применено внешним слоем?”

## Когда Это Полезно

Factoriat особенно полезен, когда:

- условий становится много;
- одно и то же решение повторяется в разных местах;
- нужно тестировать бизнес-решение без инфраструктуры;
- хочется сохранить доменную типизацию Go;
- side effects должны оставаться во внешнем слое.

## Когда Это Не Нужно

Factoriat может быть лишним, если:

- условие одно и оно простое;
- логика почти полностью состоит из side effects;
- решение не повторяется;
- правила должны редактироваться не разработчиками через UI.
